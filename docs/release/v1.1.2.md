# PBIP v1.1.2 release notes

Tagged `v1.1.2` on 8 November 2026 from `main`; the tagged commit and its checks are listed on the
[GitHub release](https://github.com/rachitst/pbip/releases/tag/v1.1.2). The full list of changes is in
[`CHANGELOG.md`](../../CHANGELOG.md), and the staging measurements are in
[performance 2026-11-08](../testing/performance-2026-11-08-oci.md).

## In plain language

- **Staging is on HTTPS with a real certificate.** `https://pbip.duckdns.org` now has a Let's Encrypt certificate
  that browsers trust, and releases reach it through the automatic Deploy workflow, which checks the site after
  every deployment and rolls back if the check fails.
- **The fraud and recommendation models run on staging**, the same trained models the demo uses, if the operator
  switches them on. Without them, or if they ever fail to load, the rules decide, as before.
- **The assistant wastes less time.** Each customer can now send 10 open questions a minute to the fast AI service
  (was 5). Past that, the assistant answers from its built-in rules immediately instead of trying a slow local
  model first.
- **Measured on staging:** every page loads within 2 seconds and signing in takes under a second. Under heavy load
  the small free server stays correct (no errors, every balance right) but slows down; that limit is the server's
  size, not the code.

Nothing changes for customers' data or money movement.

## Upgrade notes

- No database migration (the schema stays at `0031`).
- `RATE_LIMIT_GROQ_PER_MINUTE` defaults to 10 (was 5). A used budget, or Redis being unreachable (the budget fails
  closed), now means the keyword rules answer, not Ollama (ADR-0037 addendum).
- To serve the trained models on a deployed host: copy `models/fraud` and `models/recommendations` to `~/pbip/models`,
  set `ML_MODELS=enabled` in the host `.env` and deploy (deploy guide section 14.1, ADR-0061). With models on, a
  hand-run `docker compose ... up` must name both compose files (runbook section 2.3).
