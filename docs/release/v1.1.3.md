# PBIP v1.1.3 release notes

Tagged `v1.1.3` on 8 November 2026 from `main`; the tagged commit and its checks are listed on the
[GitHub release](https://github.com/rachitst/pbip/releases/tag/v1.1.3). The full list of changes is in
[`CHANGELOG.md`](../../CHANGELOG.md).

## In plain language

- **Releases no longer take the site's API offline.** Until now a new version replaced both copies of the API at
  once, and the site stopped answering for about 12-15 seconds. Now the new copies start first and must prove they
  are healthy; only then are the old ones switched off, one at a time, after finishing what they were doing. A new
  version that does not start properly never receives traffic, and the old one keeps running.
- **One short gap remains.** The web server in front of the API is still swapped at the end of a release, because
  only one container can hold the site's ports.

Nothing changes for customers' data or money movement.

## Upgrade notes

- No database migration (the schema stays at `0031`).
- From this release, migrations run while the previous release is still serving. A migration must leave the schema
  usable by the release before it: add first, remove in a later release (runbook section 2.1).
- `API_REPLICAS` in the host `.env` (default 2) sets how many new replicas a release starts; a value outside 1-99 is
  refused before anything changes.
- For a few seconds during a release the host runs twice the usual number of API containers.
